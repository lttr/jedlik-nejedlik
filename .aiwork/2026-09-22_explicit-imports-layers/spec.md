# Spec — Selective explicit imports in Nuxt layers

## Why

Auto-imports hide the dependency graph from the agents that do most of the work
here: nothing in the source says where `useCart` comes from, collisions across
layers resolve silently by layer priority, and dead-code and boundary tools
cannot follow edges that exist only in `.nuxt/`.

Out of scope: composable and component overrides between layers. We don't use
them.

## Target state

| Code                                                | Import style                                                                   |
| --------------------------------------------------- | ------------------------------------------------------------------------------ |
| Vue and Nuxt core (`ref`, `useFetch`, `navigateTo`) | Auto-imported                                                                  |
| Module-provided composables (`useI18n`, Pinia)      | Auto-imported — modules register via `addImports`, unaffected by `scan: false` |
| Own composables, utils, `shared/`                   | Explicit                                                                       |
| Own components                                      | Explicit                                                                       |
| h3 / Nitro core (`defineEventHandler`, `readBody`)  | Auto-imported                                                                  |
| Own `server/utils`                                  | Explicit                                                                       |

**Scope: all our own code**, layers and non-layer root alike. `web/app/`,
`web/shared/` and `web/server/` are internal code on the same footing as a layer
— effectively a base layer — and behave identically. **They are not promoted into
a real `base` layer** (decided 2026-09-22): behaving like one is enough, and a
small amount of genuinely global pages, components and composables living at the
root is fine. Amended the same day after measuring the graph: the root is the
_top_ of Nuxt's extends chain, yet ten layer pages use root's `PageWrapper`. So a
**small `layers/base`** takes only what layers reach up for — `PageWrapper` and
`watchAsyncDataError` today — and sits at the bottom, below `directus`. The root
keeps everything else. The `~/` spelling and the `app` fallow zone stay as the only two
places the root differs. This is not optional either
way: `imports.scan` is read from the merged config, so turning it off is global
and the root's 6 composables, 2 utils and 4 `shared/utils` files stop being
auto-imported the moment step 3 lands.

Specifiers — one rule, with the alias that applies where you are:

- Siblings and one level up: relative (`./`, `../`).
- Anything further: **an alias, never a relative chain**. Inside a layer that is
  `#layers/<name>/...`, generated by Nuxt for every layer under `layers/` (3.16+)
  and pointing at its **root dir** (verified in `@nuxt/kit` 4.5.2 and
  `.nuxt/tsconfig.json`: `#layers/shop/*` → `../layers/shop/*`), so
  `#layers/shop/server/utils/x` and `#layers/shop/shared/utils/x` both work. In
  the root app it is `~/...`. One canonical
  specifier per module keeps grep and codemods cheap.
- Never `~/` or `@/` _inside a layer_ — there they resolve against the consuming
  app, not the layer. This is the one place the two locations differ, and it is
  the reason the rule names an alias per location rather than a single spelling.

Deep imports into another layer stay allowed. **No layer encapsulation** — no
public `index.ts`, no deep-import ban. It is a separate feature and not worth
pursuing now (decided 2026-09-22): the fallow boundary rules already stop the
wrong layer from importing at all, and an entry file would only add a finer gate
on top, with an export list to maintain per layer. Revisit if a layer's internals
start churning or one is ever published.

**Components and `Lazy*`.** `components: false` removes the scan, and with it
the `Lazy` prefix, `.client.vue`/`.server.vue` wrappers and islands. An inventory
at `1e0f8e4` found none of those in use. Lazy loading survives without the
prefix — it is what `<LazyFoo>` compiles to:

```ts
const HeavyChart = defineAsyncComponent(() => import("./HeavyChart.vue"))
```

So: `components: false` everywhere, `defineAsyncComponent` instead of `<Lazy*>`,
convention recorded in `CLAUDE.md`. If that grates in practice, the fallback is a
scan kept for one `components/lazy/` dir in the layer that needs it — reversible
and opt-in.

## Config

`web/nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  imports: { scan: false },
  components: false,
})
```

`imports.scan` is read from the merged config, so the root covers every layer.
`components` is not: `components/module.ts` normalizes it per layer, and an unset
value expands to that layer's default dirs. So `components: false` also goes in
each of `base`, `auth`, `directus`, `lms`, `shop` — and in the nested
`layers/shop/mock-gopay`, whose config also sets `$meta: { name: "mock-gopay" }`
for its `#layers/` alias.

Server side, same rule: our own `server/utils` explicit, h3 and Nitro core
auto-imported. `NitroOptions.imports` is typed `UnimportPluginOptions | false`
(verified in nitropack 2.13.4) — there is **no `scan` key**; that one is Nuxt's.
So `nitro: { imports: false }` is all-or-nothing and would take
`defineEventHandler` with it. The route to try instead is emptying the scanned
dirs while leaving the presets that carry core:

```ts
nitro: {
  imports: {
    dirs: []
  }
}
```

Unverified: Nitro populates those dirs itself, and whether an empty array
survives its config merge has to be proven on the running build, not assumed.
Step 3 does that. If it cannot be split, server-side auto-imports stay and this
becomes a follow-up rather than a silent regression of the core rule.

A `nuxt prepare` is still needed on a fresh checkout, since `#layers/*` paths and
the remaining core auto-import types live in `.nuxt/`. The `nuxt:prepare` task
already guarantees this for every type-aware check.

## Rules

Two tools: oxlint checks the import string on every edit, fallow checks the
resolved file graph in pre-commit and CI.

**Specifiers** — two `lint.overrides` entries in `vite.config.ts` (vite-plus owns
oxlint here; there is no `.oxlintrc.json`). They differ only in whether `~/` is
allowed:

```ts
{
  files: ["web/layers/**"],
  rules: {
    "no-restricted-imports": ["error", { patterns: [
      { group: ["~/*", "~/**", "@/*", "@/**", "~~/**", "@@/**"],
        message: "Aliases resolve against the app, not the layer. Use #layers/<name>/." },
      { group: ["../../*", "../../**"],
        message: "Use #layers/<name>/ beyond one level up." },
      { group: ["#imports"],
        message: "Import from 'vue', '#app' or the source file." },
    ] }],
  },
},
{
  files: ["web/app/**", "web/shared/**", "web/server/**"],
  rules: {
    "no-restricted-imports": ["error", { patterns: [
      { group: ["../../*", "../../**"],
        message: "Use ~/ beyond one level up." },
      { group: ["#imports"],
        message: "Import from 'vue', '#app' or the source file." },
    ] }],
  },
}
```

Two gotchas: `*` does not cross `/`, hence every pattern twice; and an override
replaces the rule's options rather than merging, so it must carry the full list.

**Dependency direction** — a `boundaries` block in the existing
`.fallowrc.jsonc`:

```jsonc
{
  "boundaries": {
    "zones": [
      { "name": "app", "patterns": ["web/app/**"] },
      // Before `layers`: first match wins, so this carves the nested layer out of `layers/shop`.
      { "name": "mock-gopay", "patterns": ["web/layers/shop/mock-gopay/**"] },
      // No `patterns` on the parent: every file lands in a child, and a
      // parent with a pattern that matches 0 files prints a WARN on every run.
      { "name": "layers", "autoDiscover": ["web/layers"] },
    ],
    "rules": [
      { "from": "app", "allow": ["layers"] },
      { "from": "layers/base", "allow": [] },
      { "from": "layers/directus", "allow": ["layers/base"] },
      { "from": "layers/auth", "allow": ["layers/base", "layers/directus"] },
      { "from": "layers/shop", "allow": ["layers/base", "layers/directus", "layers/auth"] },
      {
        "from": "mock-gopay",
        "allow": ["layers/base", "layers/directus", "layers/auth", "layers/shop"],
      },
    ],
  },
  "rules": { "boundary-violation": "warn" },
}
```

**The direction, in words.** Layers are a stack and imports only point _down_:

    app (root)  →  mock-gopay  →  shop  →  auth  →  directus  →  base

A layer may import from any layer below it, never from one above, never from
a sibling, and **never from the root** (`web/app`, `web/shared`, `web/server`):
the root is the top of Nuxt's extends chain and may import from every layer.
Anything two layers both need lives in the lowest layer that needs it, or in
`base` when it is generic UI. The allow-lists above are measured (see „Measured
direction"): `lms` has no rule until it has files, and the rules hold once the
two cycles in the backlog are cleared in step 5. Siblings are isolated
unless listed; files outside a zone are unrestricted. Starts at `warn`, moves to
`error` when the backlog is clean.

Most of the wiring already exists: `check:fallow` runs `fallow audit --quiet`
inside `check:all`, the pre-commit hook runs `check:all`, and `audit.gate` is
already `"all"`. What's left for agents is `fallow guard <file>` before
cross-layer edits, and the fact that explicit imports finally make fallow's
dead-code report meaningful.

## Migration

Mechanical, one or two commits per layer, `vp run check:all` green at each step.

1. **Inventory.** `vp run nuxt:prepare`, then read `web/.nuxt/imports.d.ts` and
   `web/.nuxt/components.d.ts`. Everything not from Vue, Nuxt or a module is a
   symbol to rewrite. Re-check for `.client.vue`, `.server.vue`, `Lazy*` and
   islands — the numbers must be fresh, not inherited from this spec.
2. **Rewrite imports**, lowest layer first (`directus`), then the root
   `web/app/`, `web/shared/` and `web/server/` as their own pass. Install antfu's
   `nuxt-eslint-auto-explicit-import` with `@nuxt/eslint` and `eslint --fix` the
   layer; it inserts an explicit import for every auto-imported symbol used. Then
   codemod the inserted `#imports` specifiers into source files (relative or
   `#layers/<name>/`) and `vue`/`#app` for core APIs. Remove the module
   afterwards — it is experimental and only needed here.
3. **Flip config.** `imports: { scan: false }`, `components: false` per the
   section above, and `nitro: { imports: { dirs: [] } }` — then `vp run
check:all`. Anything still riding an auto-import fails here. Confirm in the
   same step that h3 core (`defineEventHandler`) still resolves without an
   import; if it does not, the server side is split off as a follow-up.
4. **Rules at `warn`.** Add the oxlint override and the fallow boundaries. Check
   with `fallow list --boundaries` that zones and `#layers/*` resolution are what
   we think, and baseline with `fallow dead-code --save-baseline` if the backlog
   is large.
5. **Clean the backlog.** Fix violations layer by layer; where one reveals a real
   dependency pointing the wrong way, move the code down a layer rather than add
   an allow-rule. Known today: create `layers/base` and move `PageWrapper` and
   `watchAsyncDataError` into it; split `shop/shared/utils/pending-checkout.ts`
   (cookie helpers to `base`, redirect part to `auth`); move `muj-ucet.vue` to
   `shop`. `MainNav.vue`'s `useAccount` is a legal `app → auth` edge and stays. Also drop the `web/layers/*/{app,shared,server}/**` entry
   points from `.fallowrc.jsonc` — they exist only because auto-imports made
   those files look unreachable — and fix the dead code that surfaces.
6. **`boundary-violation` to `error`.** Four lines in `CLAUDE.md`: specifier
   conventions, `fallow guard <file>` before cross-layer edits, `nuxt prepare`
   after checkout, `defineAsyncComponent` instead of `<Lazy*>`.

Steps 2 and 5 suit agents — repetitive, verified by typecheck and lint. Step 1
and the component call are human.

## Open questions

Answered 2026-09-22 (fallow 3.27.0, Nuxt 4.5.2, `@nuxt/kit` 4.5.2):

- [x] **Child zone names work in `allow`.** Proven with a scratch config:
      `fallow list --boundaries` prints `layers/auth → layers/directus` and
      `fallow check` reports `layers/auth → layers/shop` edges as violations.
      A parent name in `allow` expands to all children (`app → layers` listed as
      `layers/auth, layers/directus, layers/lms, layers/shop`). Two findings on
      the way: fallow follows `.vue` component imports too, and a parent zone
      that carries `patterns` matches 0 files (every file lands in a child) and
      warns on every run — hence no `patterns` on `layers` in the config above.
- [x] **`defineAsyncComponent` is already the practice.** No `<Lazy*>`,
      `.client.vue`, `.server.vue` or island exists (re-checked today), and
      `layers/shop/app/utils/sales-content.ts` already builds its registry with
      `defineAsyncComponent(() => import(...))`, deliberately, for chunking and
      for plain-vitest importability. Nothing to decide; no scoped scan.
- [x] **`mock-gopay`: `#layers/mock-gopay` via `$meta.name`, own zone.**
      Nuxt names a layer after its directory only for auto-scanned `layers/*`;
      an `extends` layer gets an alias only if its config sets
      `$meta: { name: "mock-gopay" }` (docs „Named Layer Aliases", kit source
      `#layers/${layer.meta.name}` → its root dir). Nobody imports _into_
      `mock-gopay` today, so the alias is for symmetry; the other direction
      matters: its three routes and one page reach `shop` through 5–7-deep
      relative chains (`../../../../../server/utils/gopay-client`), which become
      `#layers/shop/server/utils/gopay-client`. Since the alias exists only in
      mock mode, it is also the only mode in which those files typecheck — same
      as today. In fallow it is a separate zone `mock-gopay` listed _before_
      `layers` (first match wins; otherwise its 5 files fold into `layers/shop`),
      rule `mock-gopay → layers/shop`; verified in `fallow list --boundaries`.
- [x] **Real direction: measured**, see „Measured direction" below.

## Measured direction

Measured 2026-09-22 from `.nuxt/imports.d.ts`, `components.d.ts` and `types/nitro-imports.d.ts` plus explicit imports,
comments stripped (script: scratchpad `analyze.mjs`). Cells are files /
(file, symbol) pairs, client and server combined:

| from ↓ to → | root  | auth    | directus | shop   |
| ----------- | ----- | ------- | -------- | ------ |
| root        | —     | 1 / 1   | 8 / 13   |        |
| auth        | 5 / 5 | —       | 4 / 7    | 3 / 10 |
| directus    |       |         | —        |        |
| shop        | 4 / 5 | 20 / 33 | 20 / 62  | —      |
| mock-gopay  | 1 / 1 |         |          | 4 / 16 |

`directus` has zero outgoing edges and `lms` is an empty marker layer
(only `nuxt.config.ts`), so the guessed bottom is right and the `lms` rule
is untested. The guess is wrong in two places, both real cycles:

1. **`auth ↔ shop`.** `shop/shared/utils/pending-checkout.ts` imports
   auth's `redirects`, and `prihlaseni.vue` and `overeni-emailu.vue`
   import it back (`takePendingCheckoutSlug`, `authRedirectTarget`,
   `pendingCheckoutPath`); `muj-ucet.vue` renders shop's
   `AccountMyCourses` and `AccountBilling`. Splitting `pending-checkout`
   (cookie helpers below both, redirect part in auth) clears 7 of the 10
   pairs; the account page is a shop page and moves there.
2. **`layers/* → root`, and `root → auth`.** Ten layer files (five auth
   pages, four shop pages, the mock page) use root's `PageWrapper`, one
   shop page uses `watchAsyncDataError`; `MainNav.vue` uses auth's
   `useAccount`. Nuxt's extends direction makes the root the top layer, so
   these are inverted and the `app → layers` rule alone cannot hold.
   `PageWrapper` and `watchAsyncDataError` have to move below `auth`.
   **Decided 2026-09-22: a small `layers/base`** holds them (see „Target
   state"); `directus` was the no-new-layer alternative and lost on
   naming.

Corrected allow-list, enforceable once 1 and 2 are done:
`base → ∅`, `directus → base`, `auth → base, directus`,
`shop → base, directus, auth`, `mock-gopay → base, directus, auth, shop`,
`app → everything`, `lms` omitted until it has files. Until then the two cycles are the step-5 backlog
(10 + 11 pairs), not allow-rules. `web/tests/**` imports all three layers
and stays outside every zone.
